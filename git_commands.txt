GIT COMMANDS USED IN THIS ASSIGNMENT
Author: Aditeey Singh
====================================================================

STEP 1: LOCAL REPOSITORY SETUP
--------------------------------------------------------------------
mkdir git-workflow-demo && cd git-workflow-demo
    Creates the project folder and moves into it. (index.html and
    about.html were then created inside this folder.)

git init -b main
    Initializes a new, empty Git repository in the current folder and
    names the default branch "main".

git status
    Shows the state of the working directory and staging area
    (untracked, modified and staged files).

STEP 2: GIT WORKFLOW EXECUTION
--------------------------------------------------------------------
git add index.html about.html
    Stages the two HTML files so they are included in the next commit.

git commit -m "Initial commit: add index.html and about.html"
    Records the staged snapshot as the first commit, recording the
    initial state of the project.

git diff
    Shows the line-by-line changes made to tracked files that have not
    been staged yet.

git add about.html
git commit -m "Update about.html: add author details"
    Stages the modified about.html and records it as the second commit.

git branch feature
    Creates a new branch called "feature" pointing at the current commit.

git switch feature
    Switches the working directory to the "feature" branch
    (equivalent to: git checkout feature).

git branch
    Lists all local branches; the current branch is marked with "*".

git add index.html
git commit -m "Add features section to index.html (feature branch)"
    Stages and commits the index.html change on the feature branch only.

git switch main
    Switches back to the main branch (equivalent to: git checkout main).

git merge --no-ff feature -m "Merge branch feature into main"
    Merges the feature branch into main. --no-ff forces a merge commit
    so the branch activity remains visible in the history.

git log --oneline --graph --all --decorate
    Displays the commit history of all branches as a compact graph,
    showing branch names and where branches split and merge.

git log --stat
    Displays the full commit history with author, date, message and the
    files changed in each commit.

STEP 3: .gitignore IMPLEMENTATION
--------------------------------------------------------------------
cat .gitignore
    Prints the .gitignore file, which contains the rules "*.log"
    (ignore all log files) and "temp/" (ignore the temp folder).

git status --ignored
    Shows the repository status including the files that Git is
    ignoring (debug.log and temp/).

git check-ignore -v debug.log temp/notes.txt
    Confirms that the given paths are ignored and prints which line
    of .gitignore matches each one.

git add .gitignore
git commit -m "Add .gitignore to ignore *.log files and temp/ folder"
    Stages and commits the .gitignore file so the rules are shared.

STEP 4: UNDO OPERATION
--------------------------------------------------------------------
git add contact.html
git commit -m "Add contact.html (commit to be undone)"
    Makes an additional commit that will be undone.

git log --oneline -3
    Shows the last 3 commits in one-line format.

git revert --no-edit HEAD
    Undoes the last commit by creating a new commit that reverses its
    changes (contact.html is removed). History is preserved, so it is
    safe for repositories that are shared or pushed.

git show --stat HEAD
    Shows details of the latest commit (the revert commit) and the files
    it changed.

(Alternative, not used here: git reset --hard HEAD~1 moves the branch
back one commit and discards it from history; git reset --soft HEAD~1
does the same but keeps the changes staged.)

STEP 5: GITHUB INTEGRATION
--------------------------------------------------------------------
git remote add origin https://github.com/<username>/git-workflow-demo.git
    Links the local repository to the empty public GitHub repository
    under the name "origin".

git remote -v
    Lists the configured remotes and their fetch/push URLs.

git push -u origin main
    Uploads the main branch and its full commit history to GitHub and
    sets origin/main as the upstream for future pushes.

git push origin feature
    Uploads the feature branch so the branch also appears on GitHub.

git log --oneline --graph --all --decorate
    Re-checks the history; origin/main and origin/feature now appear,
    confirming that the push succeeded.

STEP 6: COMMAND DOCUMENTATION
--------------------------------------------------------------------
git add git_commands.txt
git commit -m "Add git_commands.txt documenting all Git commands used"
    Stages and commits this documentation file into the repository.
